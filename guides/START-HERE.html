دليل تفعيل منصة تمكين أب

نسخة 1.0 — 3 أكتوبر 2026. هذه الحزمة تحتوي المنصة وبرمجتها وقاعدة بياناتها. لم تُنشأ حسابات خارجية أو يُنشر مستودع في حسابك بعد؛ يحتاج التشغيل الفعلي إعداد حساباتك وفق الخطوات التالية. لا تحتاج شراء نطاق أو استضافة أو اشتراك لتبدأ.

ما الذي ستفعّله؟

GitHub Pages يستضيف واجهة الموقع. Supabase Free يحفظ الحسابات والدورات والتقدم والملفات ويصحح الاختبارات على الخادم. Google OAuth يتيح الدخول بحساب Google دون إنشاء كلمة مرور في المنصة. لا تطلب المنصة قراءة Gmail أو Drive.

حساب الإدارة الوحيد هو lenovohayan@gmail.com عند دخوله عبر Google ببريد مؤكد. تغيير اسم المتدرب أو تعديل متصفحك لا يمنح صلاحية الإدارة. التسجيل في Supabase بحسابك وحده لا يُعد تسجيل دخول إلى المنصة؛ ستدخل لاحقاً من زر Google داخل الموقع.

1. فك الحزمة والتعرف على الملفات

فك ضغط tamkeen-up-complete.zip على الكمبيوتر. ستجد:

المجلد / الملف فائدته
github-ready/ الموقع المبني الجاهز للرفع؛ لا يحتاج تثبيت برامج
source/backend/setup.sql إنشاء قاعدة البيانات والصلاحيات والتصحيح والتخزين
guides/START-HERE.html هذا الدليل بتصميم عربي يعمل دون إنترنت
guides/ADD-COURSE.html إضافة الدورات والأسئلة والشهادات
guides/COURSE-PROMPT.txt البرومبت لتحويل الحقيبة التدريبية إلى دورة
examples/course-example.json دورة أصلية قصيرة لاختبار الاستيراد والتصحيح
certificate-assets/ شعارك والختم وقالب خلفية شهادة فارغ
source/ الشيفرة الكاملة والاختبارات وملفات التطوير

ارفع محتويات github-ready فقط إلى المستودع العام. لا ترفع حقائبك الخام أو ملفات الدورات الحقيقية التي تحتوي الإجابات أو نسخ بيانات المتدربين إلى GitHub. استيراد الدورات ورفع موادها يتمان من لوحة الإدارة إلى Supabase.

2. إنشاء مستودع GitHub مجاني

  1. افتح https://github.com وسجّل الدخول إلى حسابك، أو أنشئ حساباً مجانياً.
  2. اختر New repository. سمّه tamkeen-up، واختر Public للخطة المجانية.
  3. فعّل Add a README file ثم أنشئ المستودع.
  4. افتح Add file → Upload files. اسحب كل الملفات والمجلدات داخل github-ready إلى نافذة الرفع. يجب أن يظهر index.html مباشرة في جذر المستودع، وبجانبه config.js ومجلدا assets وguides. لا ترفع ZIP ولا مجلداً اسمه github-ready يحيط بهذه الملفات.
  5. اضغط Commit changes. إذا لم يظهر الملف .nojekyll ضمن الرفع، أنشئه من Add file → Create new file؛ اسم الملف .nojekyll ومحتواه فارغ، ثم احفظه.
  6. افتح Settings → Pages. تحت Build and deployment اختر Deploy from a branch، ثم الفرع main والمجلد /(root)، واضغط Save.
  7. انتظر نجاح النشر. ستعرض صفحة Pages الرابط الفعلي. انسخه؛ شكله المتوقع https://اسم-حسابك.github.io/tamkeen-up/. هذا مثال فقط؛ استخدم الرابط الذي يعرضه GitHub بالضبط.
  8. افتح الرابط. تظهر نسخة معاينة محلية مع شريط يوضح أنها تجريبية. هذا طبيعي قبل تفعيل قاعدة البيانات؛ أزرار التجربة لا تُستخدم كحسابات حقيقية.

3. إنشاء مشروع Supabase Free

  1. افتح https://supabase.com/dashboard وأنشئ حساباً أو سجّل الدخول.
  2. اختر New project داخل منظمة مجانية Free. سمِّ المشروع tamkeen-up، واختر المنطقة المناسبة، وأنشئ كلمة مرور قاعدة البيانات واحفظها لديك. لا ترسلها في المحادثة.
  3. انتظر اكتمال تجهيز المشروع، ثم افتح SQL Editor → New query.
  4. افتح محلياً source/backend/setup.sql بمحرر نصوص، وانسخ محتواه كاملاً إلى SQL Editor واضغط Run.
  5. يجب أن تنتهي العملية بنجاح. الملف يُنفذ مرة واحدة على مشروع جديد. إذا ظهر خطأ، احتفظ بنصه؛ لا تحذف السياسات ولا تعطل RLS لحله. الملف داخل معاملة واحدة، فيتراجع الإنشاء إن فشل.
  6. من Table Editor تأكد من وجود courses وcourse_content وcategories وprofiles وcertificates. جدول categories يحتوي 16 تخصصاً قابلاً للإضافة والتعديل.
  7. من Storage تأكد من وجود course-files بوضع Private، وbrand-assets بوضع Public. الأول للمادة العلمية، والثاني لصور الأغلفة وقوالب الشهادة العامة.
  8. من Connect أو Project Settings → API / API Keys انسخ Project URL والمفتاح العام Publishable key، أو المفتاح القديم anon public. لا تستخدم Secret key أو service_role في الموقع.

4. إنشاء تسجيل الدخول عبر Google

  1. افتح https://console.cloud.google.com بحسابك. أنشئ مشروعاً اسمه Tamkeen Up؛ إعداد OAuth لا يتطلب تفعيل خدمة مدفوعة.
  2. افتح Google Auth Platform. إن ظهرت Get started، ابدأ إعداد التطبيق.
  3. في Branding اكتب اسم التطبيق «تمكين أب»، وبريد دعمك وبريد المطوّر. إدراج شعار شاشة موافقة Google قد يتطلب مراجعة من Google؛ شعار الموقع نفسه جاهز ولا يتوقف على هذه المراجعة. ابدأ دون رفع شعار OAuth إذا أردت إكمال الاختبار أولاً.
  4. في Audience اختر External. أثناء الاختبار، أضف بريد الإدارة وبريداً آخر لك إلى Test users. بعد نجاح التجربة استخدم Publish app / In production ليتمكن جمهورك من الدخول؛ وضع Testing لا يسمح للجميع.
  5. في Data Access استخدم الصلاحيات الأساسية فقط: openid وuserinfo.email وuserinfo.profile. لا تضف صلاحيات Gmail أو Drive.
  6. في Supabase افتح Authentication → Sign In / Providers → Google، وانسخ Callback URL. شكله https://معرف-مشروعك.supabase.co/auth/v1/callback.
  7. في Google افتح Clients → Create client → Web application. الاسم Tamkeen Up Web.
  8. تحت Authorized JavaScript origins أضف أصل موقعك فقط: https://اسم-حسابك.github.io، دون /tamkeen-up/ ودون #/.
  9. تحت Authorized redirect URIs ألصق Callback URL الخاص بـ Supabase الذي نسخته. هذا الحقل لا يحتوي رابط GitHub.
  10. أنشئ العميل وانسخ Client ID وClient Secret إلى إعداد Google في Supabase. فعّل Enable Google واحفظ. السر يُحفظ في Supabase فقط، ولا يُكتب في config.js ولا GitHub ولا يُرسل في المحادثة.
  11. في Supabase افتح Authentication → URL Configuration. اجعل Site URL رابط المنصة الكامل مع المجلد والشرطة النهائية، مثل https://اسم-حسابك.github.io/tamkeen-up/. أضف الرابط نفسه إلى Redirect URLs واحفظ.
  12. من إعدادات تسجيل الدخول في Supabase، أبقِ Google مفعلاً، وعطّل تسجيل الدخول بكلمة مرور البريد ومزوّدي الدخول غير المستخدمين. لا تفعّل الدخول المجهول. المنصة توفر زر Google فقط.

التمييز بين الروابط مهم:

الموضع القيمة
Google: JavaScript origins أصل GitHub، دون المجلد
Google: redirect URIs رابط Callback من Supabase
Supabase: Site URL وRedirect URLs رابط المنصة الكامل مع المجلد

5. ربط الموقع بقاعدة بياناتك

  1. داخل مستودع GitHub افتح config.js واضغط رمز القلم Edit.
  2. ضع رابط المشروع والمفتاح العام بين علامتي الاقتباس:
window.TAMKEEN_CONFIG = {
  supabaseUrl: 'https://معرف-مشروعك.supabase.co',
  supabaseAnonKey: 'المفتاح-العام-Publishable-أو-anon'
};
  1. احفظ Commit changes وانتظر اكتمال إعادة النشر في Actions.
  2. حدّث الموقع بقوة بـ Ctrl+Shift+R. يختفي شريط المعاينة وأزرار التجربة. لا تُنقل بيانات التجربة المحلية إلى حسابات Google.
  3. اضغط الدخول بحساب Google واختر lenovohayan@gmail.com. وافق على مشاركة الاسم والبريد الأساسيين.
  4. يجب أن تعود إلى الموقع ويظهر خيار لوحة الإدارة. افتح الملف الشخصي وأدخل اسمك الكامل واحفظه.

6. اختبار فعلي قبل دعوة المتدربين

  1. من لوحة الإدارة استورد examples/course-example.json، واحفظه كمسودة، وراجع أسئلته، ثم انشره. هذا مثال أصلي للتجربة وليس محتوى مقتبساً من أبعاد.
  2. افتح الموقع بحساب Google ثانٍ. ينبغي ألا تظهر لوحة الإدارة، وألا تفتح روابط الإدارة لهذا الحساب.
  3. احفظ اسم الحساب الثاني، والتحق بالدورة، وأكمل درساً. سجل الخروج ثم عد بالحساب نفسه؛ يجب أن يبقى التقدم محفوظاً. جرّب جهازاً آخر بعد إعداد Google الفعلي.
  4. اختبر أن الدرس اللاحق مغلق حتى إتمام المتطلب السابق، وأن التقييم يعطي نتيجته فور الإرسال، وأن الإجابة الخاطئة في تقييم الوحدة لا تفتح الدرس التالي.
  5. أكمل النهائي والاستبيان. تظهر الشهادة تلقائياً في شهاداتي، ويمكن فتحها من التقدم → عرض الشهادة.
  6. افتح رابط الشهادة في نافذة خاصة لا تحتوي تسجيل دخول. تظهر الشهادة وحالة التحقق والاحتفالية. جرّب حفظها PDF وقراءة QR بالهاتف.
  7. من الإدارة جرّب إلغاء صلاحية شهادة اختبار ثم إعادة تفعيلها؛ يجب أن تتغير حالتها في رابط التحقق.
  8. أرشف دورة المثال بعد الاختبار إذا لم ترغب في إتاحتها لجمهورك. الدورات المؤرشفة تظل متاحة لمن سبق أن التحق بها.

7. إعداد الهوية والشهادة

افتح لوحة الإدارة → الإعدادات والهوية وعدّل اسم المنصة وبريد الدعم والجهة المصدرة والتوقيع النصي. القالب الافتراضي مصمم وجاهز مع شعارك وختم تمكين أب ورمز QR. يمكنك رفع خلفية PNG/JPG أفقية وتعديل مواضع الاسم والبرنامج والتاريخ وحجم الخط ولونه من المعاينة، ثم حفظ الإعدادات. راجع دليل إضافة الدورة لتفاصيل الشهادة.

8. كيف يبقى التشغيل دون دفع؟

وفق صفحات الخدمات الرسمية وقت إعداد الحزمة: GitHub Pages متاح مجاناً للمستودعات العامة. Supabase Free يوفر 500 MB لقاعدة البيانات، و1 GB للملفات، و50,000 مستخدم نشط شهرياً، و5 GB نقل بيانات مع 5 GB نقل مخزن مؤقتاً؛ رفع الملف الواحد حتى 50 MB. المشاريع المجانية قد تتوقف بعد أسبوع من عدم النشاط، والنسخ الاحتياطية الآلية ليست ضمن Free. هذه حصص قابلة للتغيير وليست وعداً باستضافة غير محدودة أو توفر دائم.

اختر Free ولا تفعّل خطة مدفوعة أو نطاقاً مخصصاً أو إضافات مدفوعة. راقب صفحة Usage. استخدم PDF مضغوطاً وصوراً مناسبة؛ للفيديوهات الطويلة يمكنك استخدام روابط YouTube غير المدرجة بدلاً من استهلاك التخزين، مع العلم أن من يحصل على رابط YouTube قد يستطيع مشاهدته خارج المنصة. إذا توقف مشروعك المجاني، أعد تشغيله من لوحة Supabase. عند بلوغ الحدود، قلّل الاستخدام أو نظّم المواد قبل التفكير في أي ترقية؛ المنصة لا تشترك نيابة عنك.

9. النسخ الاحتياطي والصيانة

  • صدّر كل دورة JSON من جدول البرامج، والإعدادات من صفحة الهوية، وتقارير CSV واستجابات التقييمات من صفحة التقارير. احتفظ بها محلياً في مكان آمن؛ تحتوي مفاتيح إجابات أو بيانات متدربين.
  • احتفظ بالملفات الأصلية المرفوعة. تصدير JSON يحفظ روابط الملفات ولا يضم بايتات PDF والفيديو.
  • هذه التصديرات ليست نسخة استعادة كاملة للحسابات. لنسخة قاعدة بيانات كاملة استخدم أدوات Supabase الرسمية، مع نسخ ملفات Storage على حدة. النسخة المجانية لا توفر ضمان استعادة تلقائية.
  • لا تحذف ملف دورة مستخدماً من Storage. إذا أصبح للدورة متدربون، استخدم نسخ إلى إصدار جديد لتغيير محتواها أو قواعد التقييم؛ السجلات السابقة لا تُعاد كتابتها. أعد رفع الملفات الخاصة للإصدار الجديد.
  • تغيير الاسم أو تصميم الشهادة بعد إصدارها لا يغيّر بيانات الشهادة القديمة. صورة الخلفية محفوظة كرابط، لذلك احتفظ بصور القوالب السابقة ولا تحذفها.
  • لتحديث التصميم لاحقاً: عدّل source، شغّل npm ci ثم npm test ثم npm run build، وارفع محتويات dist بدلاً من ملفات الموقع السابقة، مع الاحتفاظ بقيم config.js الخاصة بك. إضافة الدورات لا تحتاج إعادة بناء أو رفع GitHub.

10. معالجة المشاكل الشائعة

المشكلة الحل
موقع GitHub يعرض 404 تأكد أن index.html في الجذر، وأن Pages على main وroot، وأن النشر نجح
يظهر شريط المعاينة config.js لا يحتوي رابطاً ومفتاحاً عاماً صحيحين، أو لم يكتمل النشر/تحديث المتصفح
redirect_uri_mismatch طابق Google redirect URI مع Supabase Callback حرفياً
Google يمنع الحساب الثاني أضفه إلى Test users أثناء الاختبار، أو انشر OAuth للجمهور
العودة إلى موقع مختلف بعد Google راجع Site URL وRedirect URLs وتأكد من مجلد المستودع والشرطة النهائية
لوحة الإدارة غير ظاهرة سجّل الخروج ثم ادخل عبر Google بالبريد lenovohayan@gmail.com؛ الاسم وحده لا يمنح الإدارة
permission denied أو function not found راجع نجاح setup.sql والمشروع المستخدم؛ لا تعطل RLS
لا توجد برامج قاعدة البيانات تبدأ دون دورات؛ انشر أول دورة من الإدارة
رفع الملف مرفوض احفظ المسودة أولاً؛ راجع النوع والحجم 50 MB، والصورة 10 MB
استنفاد المحاولات الإدارة تستطيع إعادة محاولات تقييم محدد من التقارير؛ لا تحتاج تصحيحاً يدوياً
الشهادة غير صادرة راجع الاسم الكامل، وكل الأنشطة المطلوبة، ودرجة النهائي والدرجة الموزونة
تعذر تحميل البيانات بعد فترة توقف راجع حالة مشروع Supabase المجاني وأعد تشغيله إن كان متوقفاً
